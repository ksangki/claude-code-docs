# Ch.04 작동 원리

**에이전틱 루프 · 컨텍스트 조립 · 도구 실행 모델**

실무자 과정 · 사내 교육 자료

---

## 학습 목표

내부 동작을 이해하면 **디버깅과 튜닝**이 가능합니다.

- **에이전틱 루프** 6단계
- 시스템/사용자 **컨텍스트 조립**
- **도구 실행 모델**과 권한 결정 3종
- **대화형 vs 비대화형** 모드
- **서브에이전트** 스폰 메커니즘
- **대화 저장/재개/컴팩트**의 데이터 흐름

---

## 핵심 개념: 에이전틱 루프

Claude Code는 REPL이 아닌 **연속 루프**입니다.

> 요청을 읽고 → 추론하고 → 도구를 호출하고 → 결과를 관찰하고 → 반복.

작업이 완료되거나 추가 입력이 필요할 때까지 **스스로 반복**합니다.

**결과**: 한 번의 프롬프트로 다단계 작업을 자율 수행.

---

## 에이전틱 루프 6단계

**1. 사용자가 메시지를 보냄**
- 대화형 모드: 터미널 입력
- 비대화형: `--print` 또는 stdin 파이프
- 메시지는 **대화 기록에 추가**

**2. 컨텍스트 조립**
- 시스템 프롬프트, 현재 날짜, git 상태, CLAUDE.md, 도구 목록
- **대화당 한 번** 메모이제이션

**3. Claude가 추론하고 도구 선택**
- Anthropic API 호출
- 하나 이상의 `tool_use` 블록 출력 (이름 + JSON 입력)

---

## 에이전틱 루프 6단계 (계속)

**4. 권한 확인**
- 각 도구 호출 전에 모드/규칙 평가
- **자동 승인 · 확인 요청 · 차단** 중 결정

**5. 도구 실행**
- 승인된 호출 실행
- 결과(파일/출력/검색)를 **`tool_result` 블록**으로 기록

**6. 루프 계속**
- 결과를 보고 추가 도구 호출 또는 최종 응답
- **도구 호출이 더 없을 때까지 반복**

---

## 중요한 원칙: 로컬 실행

> 루프는 **전적으로 터미널 프로세스 안에서** 실행됨.

**원격 실행 서버 없음.** 도구가 명시적으로 전송하지 않는 한:
- 파일
- 셸 출력
- 자격 증명

…이 사용자 머신을 **벗어나지 않음**.

네트워크 전송 도구: `WebFetch`, `WebSearch`, MCP 서버.

이것이 **보안 검토**의 핵심.

---

## 컨텍스트 조립: 두 블록

매 API 호출 앞에 붙는 두 블록을 `context.ts`가 조립.

**시스템 컨텍스트** — `getSystemContext()`
- 현재 브랜치, 기본 브랜치
- `git user.name`
- `git status --short` (2,000자 초과 시 절단)
- `git log --oneline -5`
- 캐시 무효화 주입 (디버그용 임시)

**사용자 컨텍스트** — `getUserContext()`
- 4단계 계층(Managed → User → Project → Local)에서 발견한 모든 메모리 파일
- `Today's date is YYYY-MM-DD`

두 블록 모두 **대화 기간 동안 메모이제이션**(`lodash/memoize`).

## 도구 실행 모델

**Claude Code는 기본적으로 자율적으로 도구를 실행하지 않는다.**

각 도구에는 `checkPermissions` 메서드가 있고, 결과에 따라 동작 분기.

| 결과 | 동작 |
|---|---|
| `allow` | 도구 **즉시 실행** |
| `ask` | 루프 일시 중지 + **확인 다이얼로그** |
| `deny` | **거부** + Claude가 오류 결과 수신 |

> **실무 팁**: `Read`, `Glob`, `Grep` 같은 안전한 읽기 전용 도구는 일반적으로 **모든 모드에서 자동 승인**.

---

## 대화형(REPL) 모드

**기본 경험.** React/Ink 기반 라이브 터미널 UI.

표시되는 것:
- **스트리밍 출력** (토큰 단위)
- 도구 사용 확인 다이얼로그
- 스피너 애니메이션
- 권한 요청

메시지는 **세션 전반에 유지** → 대화 맥락이 계속 이어짐.

---

## 비대화형(프린트) 모드

활성화: `--print` 플래그 또는 stdin 파이프.

**차이점:**
- UI 렌더링 **없음**
- 출력이 stdout으로 기록
- 스크립트/CI에서 **캡처 가능**
- 일회성 자동화에 적합

```bash
echo "이 저장소 요약해줘" | claude -p --output-format json
```

---

## 서브에이전트: Task 도구

Claude가 `Task`(`AgentTool`)로 **서브에이전트 스폰**.

**각 서브에이전트는:**
- 자체 **중첩된 에이전틱 루프** 실행
- 독립된 대화 기록
- 제한된 도구 집합 (선택)
- **로컬** 또는 **원격 컴퓨팅** 실행
- 완료 시 결과를 **부모에게 반환**

활용: 병렬 탐색, 격리된 구현, 특화된 검토.

상세는 Ch.14 참조.

---

## 대화 저장 및 재개

**위치**: 기본 `~/.claude/` 안의 JSON 트랜스크립트 파일.
각 대화에 고유 **세션 ID**.

**재개 명령:**

```bash
claude --resume <session-id>
claude --resume         # 목록에서 선택
```

**재개 시 주의:**
- 전체 메시지 기록을 **디스크에서 로드**
- 메모리 파일은 **재발견** (최초 시작과 다를 수 있음)
- **권한 모드는 설정 기본값으로 재설정**

---

## 대화 컴팩션 (Compact)

긴 대화는 주기적으로 **컴팩트**됨.

**동작:**
- 가장 오래된 메시지를 요약
- 컨텍스트 윈도우를 **관리 가능하게 유지**
- 원본 트랜스크립트는 **항상 디스크에 보존**
- 컴팩트는 **API에 전송되는 내용**에만 영향

수동 컴팩트: `/compact [지시사항]`

비활성화: `DISABLE_AUTO_COMPACT=1`

---

## 쿼리 엔진 (`query.ts`)

루프의 각 "턴"은 **query** 호출.

**쿼리 엔진이 처리:**
- 실시간 토큰 **스트리밍 출력**
- `tool_use` 블록을 도구 핸들러에 **디스패치**
- 턴당 **토큰/도구 호출 예산** 적용
- 도구 결과 수집 → 다음 모델 호출 전 추가
- 컨텍스트 꽉 차면 **컴팩트 트리거**

---

## 대용량 출력 처리

각 도구에 `maxResultSizeChars` 속성.

결과가 한계 초과 시:
1. 내용이 **임시 파일**에 저장됨
2. 모델은 **파일 경로와 미리보기**만 받음
3. 필요하면 Read 도구로 파일 일부 읽기

**효과**: 대용량 출력으로 인한 **컨텍스트 오버플로 방지**.

예: 수백 MB의 build 로그, 거대한 grep 결과.

## 전체 흐름도

```
[사용자 입력]
       ↓
[컨텍스트 조립: git + CLAUDE.md + tools]
       ↓
[Anthropic API 호출]
       ↓
[tool_use 블록 생성]
       ↓
[권한 확인: allow/ask/deny]
       ↓
[도구 실행] ──→ [결과가 너무 크면 tmp 파일로]
       ↓
[tool_result 추가]
       ↓
[다시 API 호출 또는 최종 응답]
```

---

## 실무 적용 포인트

- **CLAUDE.md 최적화** = 컨텍스트 조립 효율 ↑
- **`Read`, `Grep`은 자동 승인** → 탐색 중심 세션은 쾌적
- **서브에이전트**로 병렬화 → 컨텍스트 오염 방지
- **`--resume`**으로 세션 이어가기 → 긴 리팩터링에 유용
- **`/compact`**를 작업 단위 끝에 습관화
- **대용량 결과**는 파일 경로로 올 수 있음 → 다시 `Read` 필요
